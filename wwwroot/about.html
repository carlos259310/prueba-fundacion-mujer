Enunciado de la prueba

Diseñar, desarrollar y desplegar una API REST lista para producción que permita gestionar un catálogo de productos y su stock. La API será el núcleo transaccional consumido por múltiples plataformas concurrentes.

Lenguaje y framework
.NET (C#) reciente con buenas prácticas de arquitectura
Arquitectura
Clean Architecture, Hexagonal o DDD
Base de datos
A elección del candidato (Relacional o NoSQL)
Funcionalidades requeridas
CRUD de productos · Gestión de stock · Validaciones · Swagger
Despliegue
URL pública funcional + repositorio con instrucciones claras
Decisiones técnicas
Framework .NET 8 Minimal APIs — moderno, conciso, sin controladores MVC
Arquitectura Clean Architecture — Domain / Application / Infrastructure / Endpoints
Base de datos PostgreSQL en Supabase — relacional, production-ready, gratuito
ORM EF Core 8 + Npgsql — migraciones automáticas al iniciar
Validaciones FluentValidation — reglas declarativas en capa de endpoints
Documentación Swashbuckle Swagger con enums en string y grupos por módulo
Deploy Railway + Dockerfile multi-stage — redeploy automático en cada push
Solución implementada
CRUD completo de Productos — paginado, filtro por marca, códigos únicos (409)
Módulo de Bodegas — CRUD de almacenes, stock siempre por bodega
Gestión de Inventario — vista global de stock, ajuste directo con reglas
Movimientos — Entrada, Salida y Traslado con validación de stock negativo
Reporte de movimientos — agrupado por día, filtro de fechas y producto
Validaciones robustas — FluentValidation + excepciones de dominio mapeadas a HTTP
Swagger organizado — grupos con descripción, enums en string, CSS personalizado
Seeder automático — datos iniciales si BD vacía; CLI para reset y re-seed
Deploy en Railway — Dockerfile multi-stage, redeploy automático en cada push
Interfaz visual completa — frontend Bootstrap 5 integrado, sin framework SPA

Diseño de la base de datos

PostgreSQL gestionado en Supabase. Las tablas se crean automáticamente al iniciar la API mediante migraciones EF Core. El stock se almacena por combinación producto-bodega (no existe stock global): si un producto tiene existencias en 3 bodegas, hay 3 filas en inventario. 

  ┌──────────────────────┐          ┌───────────────────────────────┐
  │       bodegas        │          │          productos             │
  ├──────────────────────┤          ├───────────────────────────────┤
  │ bod_id        INT PK │◄──┐      │ prod_id     INT  PK AUTO      │
  │ bod_nombre   VC(100) │   │      │ prod_nombre VC(200) NOT NULL  │
  │ bod_principal  BOOL  │   │      │ prod_codigo VC(50)  UNIQUE    │
  └──────────────────────┘   │      │ prod_descripcion TEXT NULL    │
             ▲               │      │ prod_marca  VC(100) NULL      │
             │               └──────└───────────────────────────────┘
             │                                    ▲
  ┌──────────┴──────────────────────────────┐     │
  │               inventario                │     │
  ├─────────────────────────────────────────┤     │
  │ prod_id  INT  FK → productos  ┐ PK      │─────┘
  │ bod_id   INT  FK → bodegas    ┘ compuesta
  │ inv_stock          INT  DEFAULT 0       │
  │ inv_last_update    TIMESTAMPTZ          │
  └─────────────────────────────────────────┘

  ┌─────────────────────────────────────────┐
  │              movimientos                │
  ├─────────────────────────────────────────┤
  │ mov_id            INT  PK AUTO          │
  │ prod_id           INT  FK → productos   │
  │ mov_bodega_inicial INT  NULL            │ ← origen  (Salida / Traslado)
  │ mov_bodega_final   INT  NULL            │ ← destino (Entrada / Traslado)
  │ mov_cantidad      INT  NOT NULL         │
  │ mov_tipo          TEXT (Entrada|Salida|Traslado)
  │ mov_concepto      TEXT (Compra|Venta|Ajuste|Traslado|Devolucion)
  │ mov_fecha         TIMESTAMPTZ NOT NULL  │
  └─────────────────────────────────────────┘

Vistas del frontend

El frontend está construido en HTML + Vanilla JS + Bootstrap 5.3.3, servido directamente por Kestrel desde wwwroot/. No hay framework SPA — cada página es un HTML independiente que consume la API con fetch().

Dashboard — /
index.html
Punto de entrada del sistema. Muestra 4 estadísticas en tiempo real (bodegas, productos, movimientos de hoy, registros de stock) cargadas con fetch al abrir la página. Incluye accesos directos a cada módulo y enlace a Swagger.
Bodegas — /bodegas.html
CRUD completo de almacenes
Lista todas las bodegas con badge visual de "Principal / Secundaria". Crea, edita y elimina bodegas mediante modales con validación en tiempo real. Confirmación antes de eliminar. Toast de éxito al guardar.
Productos — /productos.html
Catálogo paginado
Tabla paginada (10 por página) con controles de navegación. CRUD completo: crear, editar y eliminar productos con modales. Maneja el error 409 Conflict cuando el código del producto ya existe. Muestra código, marca y descripción.
Inventario — /inventario.html
Stock global con ajuste directo
Muestra todo el stock al cargar (sin seleccionar producto). Filtro opcional por producto. Ajuste directo de stock (Entrada / Salida) con selección de concepto. El stock en 0 se muestra en rojo. Previene stock negativo (error visible al usuario).
Movimientos — /movimientos.html
Historial + reporte + registro
Pestaña Historial: todos los movimientos paginados, filtro por producto, badges de color por tipo.
Pestaña Reporte: resumen por rango de fechas con 4 tarjetas + tabla diaria.
Modal Registrar: Entrada / Salida / Traslado — los campos de bodega aparecen dinámicamente según el tipo elegido.

Cómo clonar y ejecutar el proyecto
Opción 1 Correr con .NET SDK

Requiere .NET 8 SDK. No necesitas instalar PostgreSQL — la cadena de conexión a Supabase ya está en appsettings.json.

# 1. Clonar el repositorio
$ git clone https://github.com/carlos259310/prueba-fundacion-mujer.git
$ cd prueba-fundacion-mujer
# 2. Restaurar dependencias
$ dotnet restore
# 3. Iniciar la API
$ dotnet run
# Las migraciones y el seeder se ejecutan automáticamente
→ http://localhost:5080
→ http://localhost:5080/swagger
Opción 2 Correr con Docker

Solo requiere Docker instalado. No necesitas .NET ni PostgreSQL localmente.

# 1. Clonar el repositorio
$ git clone https://github.com/carlos259310/prueba-fundacion-mujer.git
$ cd prueba-fundacion-mujer
# 2. Construir la imagen
$ docker build -t productcatalog .
# 3. Correr el contenedor
$ docker run -p 5080:8080 productcatalog
→ http://localhost:5080
Comandos especiales de la CLI

Útiles durante el desarrollo para gestionar el estado de la base de datos.

# Resetear la BD (borra todos los datos)
$ dotnet run -- --reset
# Sembrar datos iniciales
$ dotnet run -- --seed
# Resetear Y resembrar en un paso
$ dotnet run -- --reset-seed
# Crear nueva migración (si cambias el modelo)
$ dotnet ef migrations add NombreMigracion
Usar tu propia base de datos

Para apuntar a otra instancia PostgreSQL, sobrescribir la cadena de conexión:

# Linux / macOS
$ export ConnectionStrings__DefaultConnection=\
  "Host=localhost;Port=5432;Database=mibd;\
  Username=postgres;Password=clave"
$ dotnet run
# O con Docker
$ docker run -p 5080:8080 \
  -e ConnectionStrings__DefaultConnection="..." \
  productcatalog
Las migraciones se aplican automáticamente al iniciar. No es necesario correr dotnet ef database update manualmente. Al arrancar con la base de datos vacía, el seeder crea automáticamente 1 bodega y 5 productos de ejemplo.
Nota sobre credenciales: La cadena de conexión a Supabase está visible en appsettings.json de manera intencional para que la prueba sea replicable sin configuración adicional. En producción real, las credenciales irían en variables de entorno y nunca en el repositorio.
Reglas de negocio y validaciones
1
Stock nunca negativo — Si la cantidad solicitada supera el stock disponible, la API responde 400 con mensaje descriptivo. Aplica tanto a movimientos como a ajuste directo PATCH.
2
Código de producto único — El campo prod_codigo tiene restricción UNIQUE en la BD. Un código duplicado devuelve 409 Conflict.
3
Bodegas obligatorias según tipo — Entrada requiere bodega destino; Salida requiere bodega origen; Traslado requiere ambas. Si falta alguna, 400 Bad Request.
4
Traslado no permitido en ajuste directo — El PATCH de stock solo acepta Entrada o Salida. Para traslados entre bodegas, usar POST /api/movimientos.
5
Inventario es upsert automático — Al registrar el primer movimiento de un producto en una bodega, el registro de inventario se crea solo (stock = 0 → ajuste). No necesitas crearlo antes.
6
Eliminación en cascada — Borrar un producto elimina su inventario y movimientos. Borrar una bodega elimina el inventario de esa bodega. Todo via EF Core Cascade.
